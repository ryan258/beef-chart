# Price evidence and refresh contract

The page loads a stored automatic snapshot and optional owner-entered quotes; it does not stream live market prices. Sources measure different populations, product forms, geographies, and intervals. USD/lb normalization does not make them identical products or purchasing opportunities.

## Sources

| Source | Native meaning | Cadence and qualification |
|---|---|---|
| BLS Average Price Data (public API v1) | U.S. monthly retail consumer-price averages, USD/lb | Valid M01–M12 rows are sorted; previous means previous available observation with its own period, not necessarily last month |
| INDEC IPC-GBA via datos.gob.ar | Greater Buenos Aires selected-item averages, ARS/kg | Monthly; retain native value if matching positive monthly FX is missing |
| IPCVA public consumer-price export | AMBA monthly retail survey averages for 22 beef rows, ARS/kg | Primary for covered cuts; native values remain usable without matching monthly FX; original Carrefour evidence is preserved |
| Carrefour Argentina catalog | Bounded sample of retailer SKU quotes, ARS/kg | On-demand; max 20 products per query, first seller, deduplicated SKUs; availability belongs to retrieval, not today |
| USDA AMS grocery features | Store-count-weighted national advertised conventional/fresh features, USD/lb | Printed PDF ad-ending window; publication is separate; prior values omitted when their interval is unknown |
| BCRA direct USD history | Monthly arithmetic mean of published USD quotes, ARS/USD | IPCVA only; current/prior months queried explicitly; separate basis and evidence from valuation rates |
| BCRA-derived datos.gob.ar FX | BCRA daily peso-per-US-dollar valuation rate, not a retail transaction quote | INDEC uses matching monthly average; catalog uses latest returned daily observation, which can lag; native U.S. prices use no FX |

Endpoints and series IDs are listed in `official_prices.py`, `ipcva_prices.py`, `bcra_fx.py` and `scrape-retail.py`. Owner-entered quotes use a separate [manual-file contract](manual-prices.md) and are not an automatic source or part of scraper writes. BLS uses its publicly available, unregistered v1 endpoint because this project has no registration key; the six-series, two-year request fits the published v1 query limits. The [datos.gob.ar Series API](https://datosgobar.github.io/series-tiempo-ar-api/reference/api-reference/) returns requested series columns in `ids` order; `last=N` returns the newest N observations in ascending date order. Monthly FX uses `collapse=month&collapse_aggregation=avg`. An endpoint is not proof of accepted transport, methodology, or reuse permission.

### IPCVA primary monthly source

`ipcva_prices.py` requests the public `vista_precios_consumidor_xls.php` export. Despite the suffix, it returns an HTML table. The adapter selects 22 known kg-priced beef product IDs, validates exact labels/column counts and Argentina-style currency amounts, and rejects duplicate, malformed, future or incomplete months. `S/D` stays missing. It promotes only values from the newest returned month; an individual missing cut retains its existing IPCVA observation with a no-match status. Current and prior available values retain their own months. Prior USD values use their own matching monthly FX.

AMBA geography and kg units were checked against the September 2026 report's table 3: all 22 prices agreed for August and September (44 comparisons). The real export fixture is `tests/fixtures/ipcva_export_2026_09.html`; discovery receipts and method notes are in `research_notes/ipcva-2026-10-15/`. The report's separate Rosario/Córdoba tables are not ingested. Prepared/non-beef rows and the frozen-hamburger four-unit price are excluded. No molleja, riñón, lengua, entraña, tapa de cuadril, pecho, aguja or specifically bone-in bife de costilla substitute is invented. Names do not establish grade, trimming or bone specifications.

The optional v2 `ar_sources` object holds current observations independently by source (`IPCVA`, `INDEC`, `Carrefour AR`). `ar` remains the selected display view, preferring IPCVA, then INDEC, then Carrefour for each available key. September IPCVA can become primary over an October retailer quote while both retain their dates. Same-source refreshes still obey monotonic date rules. A failed/missing IPCVA response retains the prior IPCVA reference. Extra survey rows appear in the price table even when no anatomical dossier maps to them.

`carrefour_originals` permanently captures every original Carrefour record once before integration. Its values, period, retrieval, availability, listings, sampling, FX and unit-scale warnings are preserved exactly, including existing one-level previous evidence. Later updates cannot overwrite these originals. Both Python and browser validators validate all source records and originals. Cut dossiers have an expandable original-Carrefour section, and the price table lists originals with their own source dates. Same-source `previous_observation` remains bounded to one version; the originals archive is additional recovery evidence, not a history of every refresh.

IPCVA conversions use matching monthly arithmetic means of the direct BCRA USD `tipoCotizacion` history from the current request. A failed or absent rate leaves native ARS/kg and null USD conversion; a single daily quote or previously saved rate is not borrowed. Partial coverage, missing FX, stale input or an export older than the previous calendar month returns nonzero after healthy evidence is saved. The request covers the previous January through the current month's first day, has a 20-second socket timeout, a 1 MB response limit and no retry. Receipt URL/hash and the methodology reference travel with each observation. The export route is not a documented API guarantee.

The October 15 FX repair keeps two distinct rate bases. The existing datos.gob.ar valuation series and its original CSV both ended on August 31, 2026 at inspection; its metadata reported `is_updated: False`. Direct BCRA USD history supplied 20 August and 22 September quote dates. Their arithmetic means were respectively 1499.925 and 1513.7727272727273 ARS/USD. Direct USD quotes are not asserted equivalent to the valuation series: Carrefour, INDEC, their stored FX values and top-level valuation FX remain unchanged by an IPCVA-only refresh.

`bcra_fx.py` uses the public `estadisticascambiarias/v1.0/Cotizaciones/USD` route, with an explicit complete-month date range and a 1000-row page. It rejects wrong currencies, nonpositive/boolean prices, invalid/duplicate/out-of-range dates, unsuccessful API status, pagination count mismatches, offsets and limit hits. Requests cover at most 24 calendar months and never the current incomplete month. A usable month requires at least 10 returned quote dates and a quote in its first and last seven calendar days. This guards against sparse/interrupted data without certifying holiday-calendar completeness; the result is the mean of returned quote days, not a published official monthly-average series or a calendar-day-weighted average.

`source_status["IPCVA FX"]` reports this independent attempt and requested-month coverage. Every converted IPCVA record retains `fx_evidence` with the source, basis, period, mean, quote count, first/last quote dates, queried range and canonical-response hash/URL. `previous_fx_evidence` identifies the previous month's own conversion inputs. Its `fx_date` denotes the monthly period start, not a daily quote. The real response is retained in `tests/fixtures/bcra_usd_2026_08_09.json`. The operator summary prints the mean and quote count for each month. A direct FX failure preserves new native IPCVA prices and the existing original archives.

Tests asserting fixed October 7 values/bytes now read `tests/fixtures/prices_legacy_2026_10_07.json`, preserving the previous corpus hash. `prices_before_ipcva.json` captures the user-refreshed snapshot immediately before integration for original-preservation checks. The working snapshot can therefore advance without changing historical test evidence.

## Minimal v2 contract

The owning validator is `price_contract.py`; browser validation enforces the corresponding rendered price/date boundary.

- `schema_version: 2`; `us`/`ar` observation objects; `fx` and `source_status` objects.
- `generated_at` describes artifact generation. Legacy `fetched` is retained for compatibility and is not universal proof of record retrieval.
- Records retain `period`, native `usd_lb` or `ars_kg`, source, and qualifiers. Positive finite prices are required; booleans, zero, negative/nonfinite values and invalid dates fail validation. AR conversion may be null while native ARS/kg remains usable.
- `retrieved_at`, `publication_date`, `prev_period`, and explicit feature boundaries have different meanings. Unknown legacy fields remain null; USDA legacy report-date labels do not become verified effective intervals.
- `market_stage`, `geography`, `method`, `provenance_status`, `observation_status`, and catalog `availability` travel with displayed values.
- Optional boolean `unit_scale_unverified: true` withholds an observation from ordinary price display, rankings, value comparisons and buying estimates, including native-price fallbacks. Cards show “Price withheld”; dossiers and the price table retain the numbers only as explicitly labeled evidence. Missing/false is not proof of verified units, availability or overall comparability. The flag belongs to the observation: qualification, failed/empty attempts and bounded previous-observation retention preserve it.
- Optional `sampling` on new Carrefour observations describes the actual bounded sample (below). Python and browser validators reject malformed counts, query evidence, seller metadata and contradictory coverage classifications. Absence means historical sampling coverage is unknown; it is not reconstructed from prices or retained listings.
- AR records disclose `fx_ars_per_usd`, `fx_date`, `fx_basis`, and `fx_provenance`. Legacy metadata inferred from the bundled snapshot is labeled inferred, not original evidence. Daily FX later than a day observation is rejected; stale rates remain visibly old.
- `source_status` and `catalog_attempts` report source/cut attempt outcome and timestamp. No match, error, legacy unknown, and successful retrieval are distinct.
- Official source states use `ok`, `partial`, `no_match` or `error`. BLS/INDEC `coverage` includes every configured series, including missing ones; INDEC `native_only` lists new observations without matching monthly FX. `FX monthly` and `FX daily` are separate attempts. `fx.monthly_retrieved_at` dates a successful monthly-rate retrieval; it does not replace the rate's observation period or the separate daily `fx.latest` evidence.
- Carrefour aggregate states use `ok` (all requested cuts returned observations), `no_match` (all empty), `partial` (observations and empty cuts), `error` (all failed), or `partial_error` (mixed failures). Cut coverage retains `ok`, `no_match` or `error`. A successful reference observation may still be inactive or unverified; this is not offer eligibility.
- New records can retain `previous_observation` for bounded recovery. This keeps one previous version, not an append-only historical store.
- Display localization (`assets/i18n.js`) operates strictly at the presentation boundary: formatting dates and decimals for Argentina and prefixing dollar amounts with `US$` in Spanish. USD displays round to two fraction digits; native amounts and FX displays use up to six, consistently across table, dossier, native fallback and retained evidence. Benchmark percentage displays use one fraction digit. Display rounding is not a transformation of stored observations. Underlying price observations, numeric amounts, currency identities, measurement units ($/lb, ARS/kg), and validation invariants are never mutated by language switching.

The bundled October 7 snapshot was qualified locally on October 12: values, record periods, legacy fetched timestamp, and August 31 latest-returned FX were not refreshed. Original raw receipts are not reconstructed. The three stored organ observations also carry `unit_scale_unverified: true`; parser regressions do not prove the cause of their unusually low nominal values.

### R30–R32 semantic rules for v2

The October 14 semantic revision retains `schema_version: 2` and does not migrate or rewrite the bundled snapshot. `price_contract.py` and the inline browser validator use the same acceptance/rejection corpus in `tests/fixtures/price_contract_v2.json` (`v2-2026-10-14`). Validation returns the supplied object without adding evidence. Qualification remains a separate operation.

- **Conversions:** when an AR record supplies both USD/lb and its own positive FX rate, validate `ars_kg / fx_ars_per_usd / 2.2046226`. Carrefour's stored two-decimal catalog conversions allow an absolute half-cent difference; INDEC and other unrounded conversions allow `1e-9`, plus `1e-12` relative floating-point tolerance in either case. Known INDEC FX dates must match the observation month. A claimed `recorded` or `inferred_from_legacy_snapshot` FX provenance requires a rate and date; neither label certifies the original receipt. Missing/null rate/date with unknown provenance stays unknown, and no top-level rate is borrowed. Native-only AR observations remain valid. Previous USD values are not recomputed without their own original inputs; complete `previous_observation` records receive the same semantic validation as current records. Arithmetic agreement never resolves original unit-scale uncertainty.
- **Dates:** observation, FX and previous periods accept real Gregorian `YYYY-MM` or `YYYY-MM-DD` values. Publication and supplied effective boundaries require full days. Partial/null effective evidence remains partial/unknown; known start/end must be ordered, and a known end must agree with the observation day or month. Supplied previous periods cannot follow the current period, and supplied FX dates cannot follow the observation or its known-by day. Monthly values do not establish ordering within their month.
- **Future windows:** validate against an explicit UTC clock (optional validator argument for deterministic fixtures; current UTC by default), bounded further by the original retrieval day when known. Generic future observations and future publication dates reject. The local USDA advertised-feature exception requires both effective boundaries and a known publication date, at most seven inclusive feature days (or at most 14 inclusive days for the explicitly marked printed USDA advertisement-ending window, with publication inside it), and an end no more than 14 days after publication. This permits bounded current/next-week advertising; it is an adapter policy, not real-report acceptance. Legacy USDA records with unknown effective ranges remain valid historical references. No dates are inferred from publication arithmetic.
- **Timestamps:** optional `fetched`, `generated_at`, retrieval, availability, last-attempt, source-attempt and FX-retrieval timestamps must be ISO strings with seconds, a timezone (`Z` or numeric offset), and at most six fractional digits. Invalid dates, zone-free text and informal dates reject; absent/null optional timestamps stay unknown. Offset timestamps use their UTC day for temporal comparisons. Timestamp shape is not a freshness or clock-synchronization guarantee.
- **States:** source/cut attempts use `legacy_unverified`, `unknown`, `not_attempted`, `ok`, `no_match`, `partial`, `error` or `partial_error`. Observation states use `legacy_unverified`, `observed`, `reference_only`, `unverified_layout`, `retained_no_match`, `retained_after_error` or `unknown`. Provenance uses `legacy_unverified`, `parsed_unverified` or `unknown`; availability uses `unknown`, `in_stock` or `out_of_stock`; FX provenance uses `unknown`, `recorded` or `inferred_from_legacy_snapshot`. Adapter/effective-period states retain their existing unresolved labels or `unknown`. Optional null record statuses remain unknown; an attempt requires an explicit recognized state. Coverage and native-only lists are typed, not proof of complete source coverage.
- **Retained metadata:** one previous observation is allowed; a non-null history chain beyond that rejects. Listings and sampling retain their optional legacy fields, while supplied amounts, stock flags, identifiers and counts are checked. JSON evidence is bounded to depth 12, 50,000 value nodes, 1,000 entries per collection and 16,384 Unicode code points per string/key. Cycles, non-JSON values, nonfinite numbers and unsafe integer values reject; shared noncyclic objects are permitted. These are post-parse contract limits, not transport-size limits. Unknown extension fields survive unchanged within those bounds.

Candidate rejection preserves the existing source-isolation and atomic-write behavior. A malformed final snapshot never replaces the last good file; an invalid browser snapshot produces the localized unavailable-data state while the reference directory/search remain usable. The refresh path now has bounded latest/backfill selection for comparable periods, but it does not archive the full stale payload or provide immutable history (R42), coverage completeness or professional acceptance.

**Validation note — organ-price units pending verification:** The stored Carrefour Argentina observations for mollejas, riñón, and lengua have unusually low native prices and should be treated as unverified unit scale. Their USD/lb conversions are mathematically consistent with the recorded inputs, but the retained evidence does not establish the original sale unit or package-weight basis; the underlying listings were also out of stock. Exclude these observations from price rankings, value comparisons, and buying estimates until the original units and availability are verified. Preserve the native values and dates for traceability, and apply a scaling correction only when supported by source evidence.

This qualification preserves 1,830, 279.9 and median 1,680 recorded as ARS/kg (respectively $0.55, $0.08 and $0.50/lb), all dated October 7, 2026, plus their original listings and FX evidence. It does not identify a per-100g or package price, and no scaling correction has been applied. Requalification needs source evidence for the original sale unit/package-weight basis and availability; a changed amount or stock label alone does not resolve these stored observations. A genuinely new observation is separate, with the flagged old record retained in `previous_observation`. The existing illustrative value treemap uses fixed teaching shares, not these or any other snapshot prices.

## Matching, parsing, and promotion

Every catalog key requires explicit raw/crudo form evidence (structured metadata or the name) and bovine evidence, an explicit x/por kg basis, structured `measurementUnit=kg` and non-boolean multiplier 1, and a positive finite quote. Prepared/wrong-species/unknown-species/pack offers fail closed. Catalog section/name alone does not establish species. Accepted listings retain unit, species evidence, seller/SKU, name, and URL. Bone-in costilla stays separate from boneless strip and T-bone; generic sweetbreads do not prove thymus.

### Carrefour sampling transparency (C14)

The adapter still requests only the first 20 products for each configured query and examines the first seller per SKU. No pagination, additional sellers or delivery-region queries were added. Each new observation records:

- `queries`: query text and actual `returned_products` before matching/filtering. Counts are per response and can overlap across aliases; they are not unique retailer product totals. `per_query_limit` records the requested maximum (20), even if a response exceeds it.
- `eligible_count`: accepted listings after the existing product-ID/SKU-ID/name deduplication. `selected_count`, also retained as the legacy `products` count, is the number used for the median. These are listing counts, not a claim of unique products across every possible title/identifier variant.
- `population`: `available_listings` when at least one accepted listing was available, otherwise `out_of_stock_references`. The latter median remains an inactive reference. Availability describes the observation, not today's inventory; unit-scale withholding continues to apply independently.
- `seller_policy: first_seller_per_sku`, distinct known `seller_ids` for selected listings, and `unknown_seller_count`. Original listing seller IDs remain intact. `region` is null because the adapter does not establish a delivery region; Argentina-wide availability or representativeness is not inferred.
- `coverage: possibly_truncated` when any query returns at least its requested limit; otherwise `unknown`. A limit hit does not prove more results exist. A short response does not prove completeness. Neither state permits an exhaustive retailer-coverage claim.

Dossiers and the existing price-table source/status column use the same sampling explanation. Historical observations without `sampling` show any recorded selected count and retained sampling note, explicitly stating that original query counts, limit hits and seller/region coverage are unknown. This is a display qualification; the stored October 7 snapshot is unchanged. Failed/empty attempts retain the original sampling evidence with the original observation; replacement keeps it in `previous_observation`. Only successful future observations can supply new query evidence.

### Other adapters and promotion

USDA's current PDF directly prints the window for advertisement **ending dates**. The adapter reads that window from the first-page heading and no longer requests the release-date page when dates are present. During the October 15 diagnostic, the PDF downloaded in 1.61 seconds while that page hit the 20-second read timeout. Only legacy reports lacking an explicit PDF interval use the page as a fallback. Failures identify `PDF download`, `Release-date page`, or `PDF text extraction` in source status; request timeouts remain bounded at 20 seconds with no automatic retry.

The adapter reads only national CW/PW/PY conventional/fresh rows. It stops at the first regional heading and resets incompatible column layouts, preventing regional price-range rows from colliding with or contaminating national columns. Store/price pairs must be complete with positive prices and positive integer store counts. Selected rows are combined by their printed store counts; the total is a count of store-feature entries, not a claim of unique stores across multiple features.

The real October 9, 2026 PDF and its layout extraction are retained as `tests/fixtures/usda_3228_2026_10_09.pdf` and `.txt`. All 11 configured cuts were checked against national row counts and prices. The PDF prints October 3–15, 2026 as its ending-date window. It does not provide explicit PW interval dates, so `prev_period` and `prev_usd_lb` remain null; old source observations survive in `previous_observation`. No dates are derived from publication subtraction. Header/column errors or missing dates fail before promotion.

New records identify `interval_basis: advertisement_ending_dates_printed_in_pdf`, the window bounds, publication date, national geography/method and PDF URL/SHA-256. The bounds describe advertisements ending in that range, not each offer's validity throughout it. Both the Python and page validators allow a marked printed ending-date window of at most 14 inclusive days, with publication inside the range and the existing publication-relative future bound. Ordinary unmarked future feature windows keep the seven-day limit. The shared corpus includes acceptance/rejection cases for this exception. Dossiers, tables and tooltips qualify the ending dates in English and Spanish. Records remain `parsed_unverified`; the fixture proves this report's adapter behavior, not every future layout or current store availability.

`python3 scrape-retail.py --usda-only` requests this source alone, validates its candidate records, preserves the one-level previous USDA evidence and atomically saves a snapshot. Failures retain native prices and original observation dates while updating attempt/status metadata. The full refresh uses the same `refresh_usda` helper. A successful parse may omit cuts not advertised in the report; empty/failed parsing remains a nonzero result.

`./fetch-prices.sh` invokes `scrape-retail.py --official`. `official_prices.py` independently requests and parses BLS, monthly FX, and INDEC using the existing endpoints/series and Python's standard library. Each request has a 20-second socket timeout and no automatic retry. IPCVA independently queries direct BCRA USD history for its actual current and prior observation months. These attempts run before the existing independent daily-FX, catalog-cut and USDA attempts. An official-source request/JSON/parser failure is recorded and does not stop other sources from being attempted. The previous internal `--official-snapshot` option still accepts a local staged file; its groups are validated independently, and an unreadable or malformed file records official failures while retail attempts continue. That option still runs the other retail requests; it is not an offline mode.

Every official source's candidate records are validated before merging. Malformed source batches are rejected as a source, with original records retained; missing individual series or successful empty responses retain their old observations as `retained_no_match`. Request/parse failures mark the affected source's retained records `retained_after_error`. Native/converted amounts, original observation/retrieval dates, FX evidence, unit-scale flags and listing evidence survive retention. Successful replacements keep the bounded `previous_observation` as before. Attempt timestamps describe the start of the current refresh, separately from the original observation dates.

Refresh promotion is monotonic for comparable observations from the same source. A candidate with an older month is retained as stale input; within a month, exact daily observations are ordered by day, and a month-only value cannot replace a stored day-level value for that month. A newer day-level value may replace a month-only value. Equal-period updates remain eligible as source revisions and preserve the prior observation in the existing one-level `previous_observation` field. Rejected stale inputs leave the stored rate and its evidence in place, record `stale_observations` with the received and retained periods, report `unknown` coverage for that key, and classify the attempt as `partial`. Older monthly or daily FX responses likewise cannot move the saved FX observation date backward; when a newer accepted daily rate is already stored, it remains available for catalog conversions. This prevents a valid replay from becoming the displayed latest value; it does not create append-only history or preserve more than the existing bounded prior observation.

INDEC conversions use only matching monthly rates from the current successful monthly-FX response. If that response fails, is malformed/empty, or lacks the relevant month, new native ARS/kg observations still advance with null USD conversion/rate/date and unknown FX provenance. Stored monthly FX and daily FX are not borrowed to fill the gap. Old converted observations remain in `previous_observation`. A monthly-FX failure/empty result retains the existing top-level FX evidence; a successful monthly update leaves the daily `latest` field intact.

Retail batches are validated against the v2 contract before merging, including keys/source identity, numeric/date/text fields, sampling and unit-scale flags. Nested product/items/sellers/offer shape errors classify as `ValueError`; HTTP failures including `IncompleteRead` are caught at daily-FX, catalog-cut and USDA boundaries. Response handles close on success or failure. A rejected retail batch retains its previous observations and does not contaminate healthy staged results.

One final validated snapshot is atomically replaced in the destination directory. A failed, empty or partial official source (including native-only INDEC coverage or a rejected stale candidate), a failed retail source/cut, or any requested catalog cut with no match produces a nonzero process result after healthy results and attempt statuses are saved. A catalog run with all empty cuts reports `no_match`, not `ok`; mixed success/no-match or a stale candidate reports `partial`. A USDA empty batch also produces a nonzero result. Missing individual advertised USDA items are retained and do not by themselves classify an otherwise parsed report as a transport failure. If every source fails, observations remain unchanged apart from retention/attempt metadata; generation time may advance without implying a price refresh. Invalid resulting data never replaces the file. This is source-level isolation, not an append-only history store or proof of live-provider compatibility.

## Operator use

The full command prints a result for each source attempted in the current run: accepted coverage, stored IPCVA month, stored FX period/date and any missing-conversion or request-failure detail. A source status of `ok` describes the request/parse result; the separately printed FX date may still lag. Expected partial refreshes exit nonzero after saving healthy results and print a concise message without a Python traceback. Unexpected programming errors still raise normally. Carrefour and USDA request failures also retain a short diagnostic note in their attempt status.

Opening or reloading the atlas reads the automatic snapshot and active manual file once each; illustrations and map redraws do not refresh or change observations. All 24 cut dossiers can be illustrated even when a price is missing or withheld. The current bundled snapshot is unchanged by the C06/C14 and artwork work.

```bash
./serve.sh
# Explicit provider refresh when wanted; updates local snapshot only:
./fetch-prices.sh
# IPCVA and direct BCRA USD monthly means only:
python3 scrape-retail.py --ipcva-only
# USDA PDF only:
python3 scrape-retail.py --usda-only
# Small catalog attempt:
python3 scrape-retail.py --cuts bife_costilla molleja rinon lengua
```

`python3 scrape-retail.py` without flags attempts daily FX, all configured catalog cuts, and USDA, leaving monthly sources alone. `--cuts` limits catalog work and skips USDA. `./fetch-prices.sh --cuts ...` additionally attempts BLS, INDEC, monthly FX and IPCVA because the wrapper supplies `--official`. Both the full refresh and `python3 scrape-retail.py --ipcva-only` request IPCVA and its direct BCRA USD quote means independently of the older valuation series. The mutually exclusive source-mode flags mean the IPCVA-only and USDA-only commands are invoked directly, without the wrapper's `--official`; neither can be combined with `--cuts`. Use `--help` without provider requests. `BEEF_PRICES_OUT` selects an alternative existing snapshot file for a deliberate refresh; it is not an offline/dry-run switch.

These refresh commands make network requests and can write attempts/qualified observations even when returning nonzero. Inspect `source_status`, `catalog_attempts`, and original observation dates before treating the result as updated evidence. Refresh remains an explicit manual command; opening the app reads stored files but does not request new prices from external providers or start a schedule. No staging, commits, publication, or automation is implicit. Prerequisites: Python 3.10+ and pdftotext for USDA; curl/jq are no longer required for this price pipeline. No paid credentials were used here.

## Owner-entered price overlay

`data/manual-prices.json` is an independent owner-edited file, loaded by the page alongside the validated automatic snapshot. Each `ar`/`us` row contains `date`, `item`, `machine_name`, numeric `price`, `currency` and `unit`. See `docs/manual-prices.md` for examples and keys. `assets/manual-prices.js` skips drafts with a null, omitted or blank date or price, then validates all completed rows before creating a display-only overlay. Unknown fields and non-object rows still reject. Zero, booleans and numeric strings are supplied values, not draft blanks. Dates must be real, nonfuture observation days; keys must match a known cut or the ground-beef benchmark; currency must be ARS or USD and unit must be kg or lb, with supported pairs ARS/kg and USD/lb; amounts must be JSON numbers that are positive, finite and at most 1000000000. Numeric strings, booleans and mixed-unit combinations reject rather than being coerced. Unknown field names and non-object rows always reject; machine names, currency, units and other required fields are checked when the row is completed. Invalid completed rows reject the manual overlay while leaving automatic evidence available. Requests time out after eight seconds.

The newest date per canonical market/key is selected, with later rows revising equal-date entries. Explicit owner quotes override automatic selection regardless of the automatic date. Manual quotes carry their own dates, native currencies/units, owner-entry provenance and unknown availability/location details. ARS quotes stay native, with null USD conversion and no inherited FX. USD quotes use their native per-pound values. No automatic source, ledger, FX input or original Carrefour record is mutated. Replaced automatic observations remain available in the evidence table and dossier; scrapers never write the manual file. Dagger-marked chart points and bilingual labels distinguish manual quotes. Source-only and manual-only country connections are supported for all 24 dossiers.

`serve.sh` keeps the other public files in its temporary copy and launches `serve_public.py`, bound to loopback. Only `/data/manual-prices.json` is read live from the project on each GET/HEAD request, with `Cache-Control: no-store`; query strings do not select other files. The live opener rejects a symlink/nonregular file or symlink data directory and caps reads at 256 KiB. An absent manual file supplies empty arrays. Saving manual-price edits and reloading is sufficient, including after atomic editor replacements; other file changes still need a restart. A server already running the former launcher needs one restart to adopt this behavior.
