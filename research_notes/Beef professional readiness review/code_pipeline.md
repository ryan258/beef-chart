## How does the implementation work, and what is actually in the snapshot?

### Takeaway
The application has a small, understandable, zero-build architecture and significantly improved failure isolation. It is currently a bilingual educational atlas backed by 36 qualified stored RETAIL observations, not a comprehensive commodity-market data system, current trading screen, procurement quotation platform, or historical database.

### Cited Findings
- `fetch-prices.sh` is a five-line wrapper: change to project directory and `exec python3 ./scrape-retail.py --official "$@"`. No scheduler or automatic update exists. `--cuts` on this wrapper still adds official attempts; direct scraper `--cuts` attempts daily FX and selected catalog cuts, skips USDA, and leaves monthly official groups alone. — [wrapper](/Users/ryanjohnson/Projects/beef-chart/fetch-prices.sh:1), [CLI orchestration](/Users/ryanjohnson/Projects/beef-chart/scrape-retail.py:270), [operator contract](/Users/ryanjohnson/Projects/beef-chart/docs/data-pipeline.md)

### Inferences
- Preserve the small static presentation and standard-library pipeline while adding explicit professional data contracts. A mandatory web framework, SaaS backend, or generic finance feed does not address the immediate evidence gaps.
- All current price populations are retail. Professional livestock/wholesale/export/commodity claims require deliberately chosen new stages, specifications, and methodology, not relabeling these observations.
- The same normalized USD/lb unit is suitable for qualified context but does not establish like-for-like purchasing equivalence among national averages, Greater Buenos Aires averages, advertised feature samples, catalog medians, bone-in/bone-out products, or differing dates.

### Gaps
- No live source calls, provider rights review, real USDA report acceptance, current stock or original organ sale-unit verification was performed or authorized. Nothing in this local review validates real upstream behavior.
- Graph query was attempted once with an 18-second subprocess bound after parent status stalled; no graph answer was captured. Treat graph evidence unresolved. Source review and offline probes provide explicit evidence, not graph all-clear.

## What confirmed corrections and residual risks remain?

### Takeaway
The recent pipeline commit is a real reliability improvement and selected regressions pass. Remaining integrity issues are mostly **P2 professional-readiness corrections**, not proof that the current snapshot contains wrong prices: latest selection can regress under replay; semantic validation is incomplete; the optional archive importer trusts source IDs and nonempty cache bytes too much.

### Cited Findings
1. **P2 — Default latest promotion can move backwards in observation time. Confirmed offline.** `merge_records` accepts any new record and replaces current; official merge checks only that period is not future. A complete staged BLS group dated 2025-01 replaces current 2026-08, source reports `ok`, and no BLS issue is returned. This can occur with stale returned/staged data; users then see an older benchmark presented as latest after a successful refresh. **Solution:** immutable observation identity + explicit latest-selection policy. Keep genuine backfills and same-period revisions as history, but default latest selects greatest qualified effective period; explicit override/replay is separate. Do not refuse useful historical observations. **Acceptance:** older BLS/INDEC/USDA batch is archived, does not displace later eligible current, and run reports stale/replayed input; same-period legitimate revisions remain possible with revision lineage. **Effort:** M, before historical analytics. — [unconditional merge](/Users/ryanjohnson/Projects/beef-chart/price_contract.py:132), [future-only guard](/Users/ryanjohnson/Projects/beef-chart/official_prices.py:185)
2. **P2 — Normalization arithmetic is not validated at the contract boundary. Confirmed offline; current stored conversions pass.** `usd_lb` and `fx_ars_per_usd` are independently checked positive, but their relationship to `ars_kg` is unchecked. Changing current lomo USD to 9999 is accepted with all native/FX values untouched. A malformed future adapter or staged import can cross a supposedly validated boundary with a materially wrong normalized amount. **Solution:** validate derived values using method-aware tolerance (catalog rounds cents; official values full precision), explicit conversion lineage and units. Permit native-only records with null USD/rate/date. Preserve legacy qualification and uncertain original units; arithmetic cannot certify the original sale unit. **Acceptance:** the unmodified snapshot passes; mismatch rejects/quarantines that source; rounded catalog and official native-only cases pass. **Effort:** S/M. — [validator](/Users/ryanjohnson/Projects/beef-chart/price_contract.py:119), [catalog conversion](/Users/ryanjohnson/Projects/beef-chart/scrape-retail.py:248), [INDEC conversion](/Users/ryanjohnson/Projects/beef-chart/official_prices.py:113)
3. **P2 — Effective interval and temporal lineage fields are not part of full validation. Confirmed boundary gap.** An existing USDA record with `effective_start: invalid`, `effective_end: 1900-01-01` passes validation; any generic observation `period: 2099-01-01` passes. Active official parsers independently reject future monthly periods, and USDA parser independently checks its intervals; the generic candidate boundary is nevertheless weaker than the professional contract needs. Future advertised intervals can be legitimate, so do not indiscriminately reject any interval ending after today. **Solution:** schema checks for valid dates and start ≤ end, period/effective-end identity, source-aware publication/effective-window plausibility, and typed retrieval/attempt timestamps. **Acceptance:** malformed/reversed intervals reject; synthetic future feature windows are accepted only according to explicit source policy; legacy unknown intervals remain unknown rather than invented. **Effort:** M. — [limited date fields](/Users/ryanjohnson/Projects/beef-chart/price_contract.py:110), [USDA dates](/Users/ryanjohnson/Projects/beef-chart/scrape-retail.py:163)
4. **P2/P3 — Previous evidence and attempt metadata are not deeply validated. Confirmed hardening opportunity.** `previous_observation: {ars_kg:-1,period:'invalid'}`, `retrieved_at:'yesterday'`, and `source_status: {BLS:{status:'gibberish',attempted_at:42}}` all pass generic validation. This is not evidence of such corruption in the bundled file. **Solution:** versioned JSON Schema or shared declarative contract; one-level previous-record validation; enumerated statuses with explicit legacy state; ISO timestamps and null semantics; cycle/size limits before rendering evidence; Python/browser parity fixtures. Avoid mandatory new metadata for qualified legacy entries. **Acceptance:** current data stays byte-identical, malformed temporal/lineage metadata fails predictably in both runtimes, documented unknowns still load. **Effort:** M. — [attempt validation](/Users/ryanjohnson/Projects/beef-chart/price_contract.py:103), [text field checks](/Users/ryanjohnson/Projects/beef-chart/price_contract.py:112), [history retention](/Users/ryanjohnson/Projects/beef-chart/price_contract.py:141)
5. **P2 — Native Carrefour evidence acquisition depends on daily FX success. Confirmed behavior, currently documented.** Daily FX failure sets `fx_row=None`, then every catalog cut raises before making its request, so fresh valid ARS/kg/availability cannot advance even though FX is only needed for derived USD. It records catalog failures even though catalog requests were not attempted. **Solution:** separate native catalog parsing from currency conversion; request/retain native evidence independently; USD null when fresh allowed FX absent; classify `dependency_unavailable/not_attempted` separately from catalog transport error. Do not silently borrow stale FX. **Acceptance:** mocked FX failure still saves new native catalog data; native/converted distinction and partial run status remain clear. **Effort:** M. — [daily FX and cut gate](/Users/ryanjohnson/Projects/beef-chart/scrape-retail.py:289), [existing behavior regression](/Users/ryanjohnson/Projects/beef-chart/tests/test_refresh_harmony.py:67)
6. **P2 — Atomic writes do not prevent concurrent-refresh lost updates. Source-confirmed risk, no destructive concurrency trial.** Both processes read independently, accumulate, then replace destination; no lock or compare-and-swap is present. A full and selected-cut refresh can overwrite each other's healthy results. **Solution:** per-output advisory lock with readable busy status, or compare source hash at promotion and explicit rebase/retry. Keep network work outside a long-held lock if using optimistic merge; never auto-merge conflicting observation identities silently. **Acceptance:** two simulated refreshes cannot silently drop either update; clear conflict/busy status; interrupted write still preserves valid snapshot. **Effort:** S/M. — [read](/Users/ryanjohnson/Projects/beef-chart/scrape-retail.py:277), [replace](/Users/ryanjohnson/Projects/beef-chart/price_contract.py:153)
7. **P2 — USDA live-layout acceptance remains a blocker for professional use of that source.** No retained accepted real report fixture, while current values are legacy unverified and synthetic parser outputs remain unresolved. **Solution:** on an owner-authorized future fetch retain report bytes, extraction, content hashes, publication/effective intervals, parsing version, and manual source-table reconciliation for representative normal/prior-only/layout-drift reports. Prefer stable official machine-readable equivalent when available and permission-compatible; research before changing source population. **Acceptance:** gold fixtures reproduce source values/store weights/date semantics; ambiguous pages fail closed; specialist accepts methodology. **Effort:** M/L plus human/provider access. — [USDA status](/Users/ryanjohnson/Projects/beef-chart/scrape-retail.py:204), [acceptance record](/Users/ryanjohnson/Projects/beef-chart/docs/data-pipeline.md)
8. **P2/P3 — Optional archive importer trusts IDs as filesystem path components. Source-confirmed potential, not exploited.** `ingredientID` from returned JSON is interpolated into `data/raw/$id.json` without numeric/slug allowlist or resolved-path containment. A hostile/malformed `../../data/prices` ID resolves to the tracked price file. Because importer is optional, inactive, and requires explicit invocation, this is limited exposure; do not present as live app exploit. **Solution:** validate exact identifier format, enforce cache-root containment, request only expected HTTPS host, use temp+validate+atomic promotion. **Acceptance:** traversal/slashes/newlines rejected before request/write; normal IDs still work. **Effort:** S/M. — [ID extraction/write](/Users/ryanjohnson/Projects/beef-chart/fetch-beef.sh:23)
9. **P2/P3 — Optional importer nonempty cache is not verified cache.** Failed `curl` can leave partial bytes; next run skips any nonempty file, then combines raw data into final JSON via direct redirection. Final-file creation truncates old output before pipeline completion. No request timeout or bounded retries is specified. **Solution:** temporary download → JSON/schema/checksum validation → atomic cache rename; retain manifest/version/request outcome; atomic final output. **Acceptance:** interrupted/bad JSON response never becomes reusable cache and cannot clobber last good output. **Effort:** S/M. — [cache/write](/Users/ryanjohnson/Projects/beef-chart/fetch-beef.sh:20), [final output](/Users/ryanjohnson/Projects/beef-chart/fetch-beef.sh:34)
10. **P3 — Upstream metadata identity and response bounds are thin.** BLS maps records by seriesID but INDEC/monthly FX assume requested column position without checking returned metadata identity/unit; HTTP reads have 20-second socket limits but no response byte limit, adaptive retries, or end-to-end operation budget. **Solution:** validate provider metadata against source registry; retain identity/unit changes as parse errors; capped body sizes, content-type checks, bounded backoff for transient errors, explicit run time budget/cancel. Keep requests deliberate and no background refresh without delegation. **Acceptance:** swapped series metadata and huge bodies fail one source; retry budget bounded; health summary explains outcome. **Effort:** M. — [monthly parser](/Users/ryanjohnson/Projects/beef-chart/official_prices.py:41), [INDEC positional mapping](/Users/ryanjohnson/Projects/beef-chart/official_prices.py:103), [transports](/Users/ryanjohnson/Projects/beef-chart/official_prices.py:34), [retail read](/Users/ryanjohnson/Projects/beef-chart/scrape-retail.py:127)
